# The Launch Film Kit: open-source tools and skills map

69 entries, vetted 2026-10-11/12 against each repo's own licence file, README and (for skills) file tree. Verdicts: 35 recommend, 32 ok-with-caveats, 2 skip. Stars and last push come from GitHub metadata fetched 2026-10-11. Machine-readable version: `tools.json`.

Legend: **R** = recommend, **C** = ok-with-caveats, **S** = skip. "Opus-native" means it works with only code, a headless browser and ffmpeg (no paid service, no GUI app).

## How to vet a skill before installing

1. **Read the licence file yourself.** No LICENSE file means all rights reserved, whatever the README badge says. Watch for noncommercial (PolyForm NC, Prosperity), copyleft (AGPL), source-available company tiers (Remotion) and vendor terms (GSAP). Check NOTICE/THIRD_PARTY files for carve-outs on fonts, music, demo footage and characters.
2. **Check the licence of what the skill pulls in, not just the skill.** An MIT skill that renders with Remotion or GSAP inherits their terms for your output pipeline.
3. **List every executable file.** Look at the repo tree for .sh, .py, .js/.mjs, package.json scripts (especially preinstall/postinstall), install.sh, .mcp.json and settings.json. Read each one that will run on your machine.
4. **Search for network and secret access.** grep for curl/wget, `| sh`, fetch/urllib, API_KEY, ~/.config, telemetry/PostHog/analytics, `@latest`, `npx -y`, `uvx`, sudo, and `--break-system-packages`.
5. **Look at the SKILL.md frontmatter and instructions.** Flag broad tool permissions (unrestricted Bash, writing outside the project), instructions to fetch and execute remote content, or to self-update.
6. **Prefer source over bundles.** Prebuilt .skill/.zip archives and minified files can differ from the visible source; build or copy from the readable files instead.
7. **Know which steps cost money.** Note every paid API (voice, music, image/video generation, cloud render) and confirm the skill has a local or offline fallback, or a spend cap.
8. **Pin versions.** Install from a specific commit or tag, vendor JS libraries locally, and disable auto-update so a later push cannot change what runs.
9. **Sandbox the first run.** Use a throwaway project folder or container with no credentials in the environment, then diff what changed on disk.
10. **Turn off telemetry** (DISABLE_TELEMETRY=1, DO_NOT_TRACK=1) for installers and engines that collect it, and optionally run a scanner such as NVIDIA SkillSpector.
11. **Check maintenance and provenance.** Last push date, open issues, whether the author is the library vendor, and whether demo media and brand marks are actually licensed for reuse.
